# splitter — AWS SDK v2 (cloud-sdk) Upgrade Design

> Module: `splitter` · Part of the ION-12317 AppianWay AWS SDK v2 upgrade program.
> **Shared foundation** (mapping, slim `appianway-commons`, config/SSM model, cloud-sdk gaps S-G2/W-G9/X-G7/X-G8, Maven template, rollout) lives on the program page — this page adds only splitter's module-specific detail.
> **Baseline (unchanged):** Dropwizard 5.0.2 / Jetty 12.1.9 / Java 17 / Jackson 2.21.4 (ION-16098, in `develop`). Both `splitter` and `ce-splitter` boot clean on that stack today (still on AWS v1 + `shared`), with the richest health-check coverage of the core apps (6 ops checks).

## 1. Overview

**Purpose:** splitter is the ETL hub's fan-out stage. It consumes a `MetaData` envelope from its pickup queue, reads the container document from the workspace bucket, runs a **strategy-pattern parser** (`MessageParserManager` → 8 Gen2 EDIFACT/ANSI/rates/XML/cfast/desktop parsers) to split a batch envelope into per-transaction child messages, authenticates/enriches each child against integration-profile/format network-services, writes child content back to the workspace bucket, and routes each child `MetaData` to a context-code-mapped next-stage queue (`format_based` router) while emitting START/CLOSE workflow lineage events to SNS.

- **Current state (DW5 baseline):** AWS Java SDK **v1** (`aws-java-sdk-sqs`) behind appianway `shared` wrappers (`SQSClient`, `S3WorkspaceService`, `SNSEventPublisher`, `EventLogger`, `networkservices.*`). Both `splitter` and `ce-splitter` boot clean and pass all 6 ops health checks.
- **Target:** `commons`/`cloud-sdk-api`/`cloud-sdk-aws` `1.0.27-SNAPSHOT` + slim `appianway-commons`. `shared` is removed entirely.
- **Headline change:** the **canonical pure-consumer rebind** ("light consumers" tier, alongside ingestor). No business logic changes. Two moves only:
  1. Rebind `ExternalServicesModule` from v1 `Amazon{SQS,S3,SNS}` builders to cloud-sdk factories (`MessagingClient[String]` listener+sender, `StorageClient`, `NotificationService`), and network-services (`AuthClient`, `IntegrationProfileByParamsService`, `FormatService`) from `commons`.
  2. Swap the v1 `com.amazonaws.services.sqs.model.Message` threaded through `SplitterTask`/`SplitErrorHandler`/`SplitTransactionProcessor` for cloud-sdk-api's `QueueMessage[String]`.
- **Explicitly NOT moving:** the 8 strategy parsers (`parser/edifact|ansi|xml|rates|cfast|desktop` + `AbstractGen2*`/`ParserUtil`/`Gen2EnvelopeParserHelper`), `RouterManager`/`FormatBasedSQSRouter`/`RouteDefinition`/`RoutingResult`, `MessageBatch`/`MessageGroup`/`GroupingHelper`, `MessageParserConfig`/`enabledParsers` — 100% appianway-domain, never touch the AWS SDK, stay **splitter-LOCAL**.

## 2. Current vs Target architecture

```
BEFORE — splitter (AWS v1 + shared)
  pickup SQS ─▶ shared SQSListener + AsyncDispatcher ─▶ SplitterTask
       SplitterTask ─▶ shared S3WorkspaceService (read container)          ─┐
       SplitterTask ─▶ MessageParserManager (8 strategy parsers) [LOCAL]    │
       SplitterTask ─▶ shared EventLogger                                    ├─▶ shared SQSClient / S3WorkspaceService / EventLogger / networkservices+AuthClient ─▶ AWS SDK v1 1.12.720
       MessageParserManager ─▶ SplitTransactionProcessor ─▶ RouterManager / FormatBasedSQSRouter [LOCAL] ─▶ shared SQSClient (route)
       SplitterTask ─▶ SplitErrorHandler ─▶ shared SQSClient (error) + EventLogger
       ExternalServicesModule builds the shared wrappers; shared networkservices.* + AuthClient feed SplitterTask

AFTER — splitter (commons + cloud-sdk-api/aws, AWS v2)   [client rebind only]
  pickup SQS (per-profile) ─▶ appianway-commons AsyncDispatcher (retained) ─▶ SplitterTask
       SplitterTask ─▶ cloud-sdk-api StorageClient.getContent (read container)
       SplitterTask ─▶ MessageParserManager (8 strategy parsers) [STILL LOCAL]
       MessageParserManager ─▶ SplitTransactionProcessor ─▶ RouterManager / FormatBasedSQSRouter [STILL LOCAL]
              SplitTransactionProcessor ─▶ cloud-sdk-api StorageClient.putObject (child, plain, no metadata)
              FormatBasedSQSRouter      ─▶ cloud-sdk-api MessagingClient[String].sendMessage (next-stage)
       SplitErrorHandler ─▶ cloud-sdk-api MessagingClient/StorageClient + NotificationService
       SplitterTask ─▶ cloud-sdk-api notification.workflow EventLogger/Event/MetaData (W-G9)
       ExternalServicesModule factory-binds cloud-sdk clients + commons networkservices.* + client.AuthClient
       cloud-sdk-aws ─▶ AWS SDK v2 BOM
```

## 4. Sequence — consume → parse/route → router SQS + SNS

```
 1.  SQSListener ─▶ SplitterTask.process(QueueMessage[String], queueUrl)
 2.  payload ─▶ MetaData (cloud-sdk-api Json)
 3.  StorageClient.getContent(bucket, fileName, ISO-8859-1)  ─▶ container envelope (read-only)
 4.  MessageParserManager.getMessageParser(metaData, content); init; validate
 5.  if parser.requiresSplitting():
        parser ─▶ List of child Message
        for each child (async, per group):
            SplitTransactionProcessor.validate(child, metaData, authProfileId) ─▶ IntegrationProfile/format (commons)
            SplitTransactionProcessor.groupMessage(batch, child)
        per group:
            SplitTransactionProcessor ─▶ StorageClient.putObject(bucket, childFileName, bytes)   [plain, no metadata → no S-G2]
            RouterManager/FormatBasedSQSRouter.routeMessage(childMetaData):
                findFormat(formatId) ─▶ contextCode
                MessagingClient[String].sendMessage(routeMappings[contextCode], childMetaData.toJsonString())
     else single document (no split):
        SplitTransactionProcessor.validate + routeToQueue ─▶ MessagingClient[String].sendMessage(routeMappings[contextCode], metaData.toJsonString())
 6.  NotificationService.publish ← EventLogger.logCloseRunEvent(CLOSE_WORKFLOW, success, tokens)
 7.  on success: AsyncDispatcher/AbstractTask ─▶ MessagingClient.deleteMessage(queueUrl, receiptHandle)
```

**Error path (`SplitErrorHandler`, retained shape):**

```
  ErrorHelper.isRecoverable(exception)?
    recoverable:
        ErrorHelper.isRecoverableAttemptsNotMaxed(queueMessage)   [FAILED_ATTEMPTS attribute, String round-trip]
          attempts not maxed ─▶ sendBackToPickupQueue(queueMessage, metaData, pickupQueueUrl) ─▶ MessagingClient.sendMessage
          maxed              ─▶ sendToQueue(metaData, pickupQueueUrl + "_dlq")                 ─▶ MessagingClient.sendMessage
    non-recoverable:
        createAnnotations(ex, ERROR_CODES, DEFAULT_ERROR_CODE)
        writeErrorsToS3(metaData, annotations, componentName, s3Bucket) ─▶ StorageClient.putObject
        sendToQueue(failureMetaData, inttra_int_sqs_subscription_errors) ─▶ MessagingClient.sendMessage
  ─▶ NotificationService.publish ← logCloseRunEvent(...)
```

Child lineage (`rootWorkflowId`/`parentWorkflowId`/`workflowId`, `Projection.{EDIID, INTEGRATION_PROFILE_ID, INTERCHANGE_CONTROL_REFERENCENUMBER, DOCUMENT_CONTROL_NUMBER, FORMAT_ID, INTEGRATION_PROFILE_FORMAT_ID, SPLITTER_FILE_SIZE, CONTEXT_CODE, FORMAT_CODE}`) built in `SplitterTask`/`SplitTransactionProcessor`/`FormatBasedSQSRouter` — **unchanged domain logic**.

## 6. cloud-sdk / commons dependencies & assumed gaps

| Gap | Relevant? | Detail |
|---|---|---|
| **S-G2** | **No.** | Splitter's only S3 write is `SplitTransactionProcessor.writeToWorkspace` → `putObject(bucket, fileName, bytes)` — the **plain, metadata-less** overload (no `ObjectMetadata`/content-type). `ErrorHelper.writeErrorsToS3` is likewise metadata-less (owned by cloud-sdk-api). Needs only the **existing** metadata-less `StorageClient.putObject` — no S-G2 dependency. |
| **W-G9** | **Yes — required.** | Splitter both **publishes** (`Projection.SPLITTER_FILE_SIZE`, `.CONTEXT_CODE`, `.FORMAT_CODE`, `.FORMAT_ID`, `.INTEGRATION_PROFILE_FORMAT_ID`, `.DOCUMENT_CONTROL_NUMBER`) and **round-trips** `Token.PICK_UP_QUEUE`/`DROP_OFF_QUEUE` and `Annotations` (`SplitErrorHandler.createAnnotations`). **`Projection.SPLITTER_FILE_SIZE` is one of the 6 constants missing from cloud-sdk-api today — splitter will not compile until W-G9.2 lands.** The `Event.Builder` annotations round-trip fix (W-G9.1) protects splitter's error-path `Annotations` from being silently dropped on any downstream re-parse. |
| **X-G7** / **X-G8** | No | no email; no ES/Jest. |
| **C-G6** | Optional | §5.3 composition works without it. |

**Consumed from commons:** `config.ConfigProcessingServerCommand` (+ appianway transform), `networkservices.*` (`IntegrationProfileByParamsService`, `IntegrationProfileFormatByParamsService`, `FormatService`, `client.AuthClient`), health base.
**Consumed from cloud-sdk-api/aws:** `MessagingClient[String]` (listener + sender), `StorageClient`, `NotificationService`, `QueueMessage[String]`, `notification.workflow.{MetaData,Event,EventGenerator,EventLogger,EventPublisher}`, `notification.annotation.{Annotations,Annotation,ErrorHelper}`.
**Moves to appianway-commons:** `AsyncDispatcher`/`Dispatcher`/`TaskFactory`/`AbstractTask`, `RecoverableException` (+ splitter's `ERROR_CODES` map stays splitter-local as *data*), health-registrar glue (`RegistryBuilder`, `OpsHealthCheckServlet`, the 6 indicator wrappers), the appianway config-transform glue.
**Stays 100% splitter-local:** `MessageParserManager`/`MessageParserConfig`, all 8 `parser/*` strategy classes + `AbstractGen2*`/`ParserUtil`/`Gen2EnvelopeParserHelper`, `RouterManager`/`FormatBasedSQSRouter`/`RouteDefinition`/`RoutingResult`, `MessageBatch`/`MessageGroup`/`GroupingHelper`/`MessageIdentifier`/`NetworkMessageIdentifier`, `SplitTransactionProcessor`, `SplitterTask`, `SplitErrorHandler`, domain exceptions, `HealthCheckConfig`, `SplitterConfiguration`.

## 10. Risks & mitigations

| Risk | Mitigation |
|---|---|
| **W-G9.2 (`Projection.SPLITTER_FILE_SIZE`) blocks compilation** | The one splitter-specific hard compile-time dependency; land W-G9 in cloud-sdk-api before splitter's pom swap (sequencing reflects this). |
| **Two-profile config drift** (`splitter` vs `ce-splitter` differ only in `publishContainerEvent`, pickup queue, SNS topic, `maxNumberOfMessages`) | Property table enumerates every difference; functional tests assert both profiles' routing tables independently. |
