**Decisions so far:** SDK CloudWatch metrics dropped ([D45](../decisions.md#d45)); control-number read by consistent `findById(SequenceId)` without the "more than one item" guard until U6 (design open issue 2); the SDK `ConditionalCheckFailedException` caught as an allowed SDK type until U10.

- **How the table is created (2026-11-20, Jenkins `AppianWay-transformer_Build` #202 log from Arijit):** CI only builds (`package -pl transformer --also-make`, Sonar), pushes images and redeploys dev with `run transformer.yaml ...`; nothing in the repo, image or CI calls `create-table`, so the tables were created once by hand. Commons' `DynamoDbAdminCommand` (booking's `dynamo-create`) does not fit: table name from a fixed `@Table` + prefix validated against `inttra2?_(prod|pr|qa|int|test|cvt)_` (CVT's `inttra2_cv_` would be rejected), default 5/5, different command name. Decision: keep `create-table` (same name, configured table, keyId S, 10/10) on `DynamoDbAdminUtil`, now idempotent. CI runs on a Linux JDK 17 image: the native-lib copy covers `.so`
- Commons 1.0.39-SNAPSHOT: `DatabaseRepository.findById(id, consistentRead)` exists; `DynamoRepositoryFactory.createRepository(DynamoDbClientConfig, table, class, repoConfig)` (enhanced client when `enableEnhancedClient`; builds two SDK clients); retry mode = SDK standard unless set (does not retry a conditional failure); `DynamoDbAdminUtil.createTableIfNotExists` + `waitForTableActive` exist; no metric publisher (U7), no consistent scan (U6), conflict not wrapped (U10)
