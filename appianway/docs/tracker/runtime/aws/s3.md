<a id="5-s3"></a>
## Objects and buckets

```bash
aws s3 ls s3://inttra2-qa-inbound-pickup/ --profile $P                                            # R
aws s3 ls s3://inttra2-qa-workspace/eventstore/2026-11-19/ --recursive --profile $P | tail -3       # R
```
`s3 ls` lists the "folders" (common prefixes, shown as `PRE`) and objects under a prefix; `--recursive` lists every object below it, with date, time, size and key. `aws s3 ls` without a bucket lists all buckets.

```bash
aws s3api head-object --bucket inttra2-qa-workspace --key <key> --profile $P \
    --query '{ContentType:ContentType,Length:ContentLength,Metadata:Metadata,ETag:ETag}' --output json   # R
```
`s3api` is the low-level API (one call per S3 operation); `head-object` returns an object's headers without its body: `Content-Type`, size, user metadata (`x-amz-meta-*`) and ETag. This is how the stored headers are compared between builds.

```bash
aws s3 cp s3://inttra2-qa-workspace/<key> "$(cygpath -w $S/stored-v1.json)" --profile $P --only-show-errors   # R
```
Downloads one object to a local file (the scratchpad) for a byte comparison with `cmp`. `--only-show-errors` hides the progress line.

```bash
aws s3api head-bucket --bucket inttra2-qa-wi01124532-rt --profile $P                                      # R
aws s3api create-bucket --bucket inttra2-qa-wi01124532-rt --region us-east-1 --profile $P                 # W (denied)
```
`head-bucket` checks whether a bucket exists and is reachable (404 = free name). `create-bucket` creates one; in `us-east-1` no `--create-bucket-configuration` is needed. Result 2026-11-19: **AccessDenied**, the QATeam role has no `s3:CreateBucket`. `get-bucket-encryption` and `get-public-access-block` were run afterwards and only confirmed the bucket does not exist.

```bash
aws s3api put-object --bucket inttra2-qa-workspace --key wi01124532-rt-ep-v1/annotations     --body "$(cygpath -w $S/annotations.json)" --content-type text/plain --profile $P --query ETag --output text   # W
```
Uploads one object from a local file with the given `Content-Type` (here the same `text/plain` the services write). The answer is the ETag. With KMS encryption the ETag is not the content's MD5, so identical bodies can show different ETags.

## Copying a real object to a marked root, and reading production

```bash
aws s3api copy-object --profile $P --copy-source "inttra2-qa-workspace/<root>/<id>" \
    --bucket inttra2-qa-workspace --key "wi01124532-rt-sp-v1-bf/BK3_Request_MinMSC" --query CopyObjectResult.ETag --output text   # W
```
Copies a real workspace object to a marked root inside the same bucket, without downloading it. With no `--metadata-directive`, S3 copies the content type and the user metadata too (checked with `head-object`). Used so that test events land under `wi01124532-rt-*` roots, not in a real file's lineage.

```bash
aws s3api list-objects-v2 --profile $P --bucket inttra2-pr-inbound-pickup --prefix 301_IFTMBC/20261119/ \
    --query 'Contents[].[Key,Size,LastModified]' --output text > iftmbc.tsv                       # R (production)
aws s3 cp --profile $P --quiet "s3://inttra2-pr-inbound-pickup/<key>" - | python -I classify2.py  # R (production), nothing saved
```
Production's buckets (`inttra2-pr-*`) are in the same account and readable with the QATeam role; queried only with Arijit's OK (2026-11-20). The listing gives keys and sizes only (it pages through every object of the prefix; 211,768 keys for one day of IFTMBC). `s3 cp <s3-url> -` writes the object to standard output, so the counter reads it and **nothing is written to disk**; `classify2.py` prints only the format and the envelope counts. `list-objects-v2 --delimiter /` at the bucket root (to list the top-level folders) scans the whole bucket: stopped, not used.

## Searching every bucket for a file (test 6)

```bash
aws s3api list-buckets --profile $P --query 'Buckets[].Name' --output text | tr '\t' '\n' | grep -i -E "map|contivo|deploy|release|artifact|build|app"   # R
aws s3 ls s3://inttra2-deployment/ --profile $P                                                                                                    # R
aws s3 ls s3://inttra2-deployment/ --recursive --profile $P | grep -i -E "IFTMBF|IFTMBC|contivo_map|maps"                                          # R
```
Looked for the map jars in the account's buckets. `list-buckets` lists every bucket name; `tr '\t' '\n'` puts one name per line (text output separates them with tabs); `grep -i` ignores case. `s3 ls --recursive` lists every key under the bucket (no folders). Found only old 2017 visibility jars and release zips: **the booking maps are not in S3**.
